# 第 114 轮：自己的联系时间未知时，首页不再给出虚假窗口

## 缺陷（来自 2026-10-02-j 的信息完整性审计）

把自己在「我的节奏」里的联系偏好设为「暂不设置，保持未知」并保存后，首页仍然给出「10月3日可以联系 · 纽约 10月3日 10:00–10:30 · 北京 10月3日 22:00–22:30」——与产品自己写的「未知时间不会算作共同空闲」相矛盾。

## 根因

首页的「我的联系时间还未设置」判断被写在 `if (!window)` 分支**内部**：

```js
const window = upcomingWindow();
const ownUnknown = canContact('me',now()) === null;
if (!window) return ...(ownUnknown ? '我的联系时间还未设置' : ...)   // ← 守卫只在没有窗口时才跑
```

也就是说：**只有在已经算不出窗口的情况下，才会去检查「我是不是未知」。** 而一旦上游仍然给出了一个窗口，这条守卫根本不会执行，页面就照常展示那个窗口。守卫的位置错了，不是内容错了。

## 本轮改动（一处）

把守卫**提到使用窗口之前**：`ownUnknown` 为真时直接返回空状态分支，不再去看上游给出的窗口。空状态文案沿用产品已有的说法：「我的联系时间还未设置 / 未知时间不会算作共同空闲」，入口是「设置我的节奏」。

## 实测

| | 首页「可联系的时间」块（节奏改为「未知」并保存后） |
| --- | --- |
| 改前 | 10月3日可以联系 · 纽约 · 10月3日 10:00–10:30 · 北京 · 10月3日 22:00–22:30 |
| **改后** | **我的联系时间还未设置 / 先告诉我什么时候方便 / 未知时间不会算作共同空闲。补充通常愿意联系的时间之后，这里才会给出下一段共同时间。/ 设置我的节奏** |

无横向溢出、无运行错误。

## 本轮**尚未送评**，原因

默认场景下改前改后截图**逐字节相同**（两者都正常显示窗口，因为默认节奏里「我」的联系时间是已设置的）。缺陷只在「先改过节奏」这个状态下出现，而固定使用途径不包含这一步。

要送评需要**第三次协议扩展**：轨道 A 增加一个「已改过节奏」的状态（类似轨道 B 增加第二个场景的做法）。这一次改的不是场景而是用户状态，是否要扩由用户决定。

## 残留（同一路径上的第二处）

同一次操作还会把右侧自己的状态行从「晚间休息」改成「夜晚」——活动标签被时段标签替换。已记录在 `design-history/2026-10-02-j/findings.md`，本轮只改一处，未处理。
