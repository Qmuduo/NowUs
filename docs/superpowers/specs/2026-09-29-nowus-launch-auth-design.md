# NowUs 首发平台与登录方案

日期：2026-09-29。

状态：目标地区组合已由用户确认；平台与登录方式为本轮推荐方案，待用户确认。本文不授权开始开发、购买服务或部署。

## 已确认的人群

第一批用户以“中国大陆一方 + 海外一方”的跨时区情侣为主，学生与上班族、作息相对固定。原型已试用，接下来解决真实账号、双方配对与同步。

## 推荐选择

| 决策 | 推荐方案 | 取舍 |
| --- | --- | --- |
| 首发平台 | 手机优先的网页应用，支持 PWA 添加到主屏 | 伴侣可以直接打开邀请链接；复用当前体验。安装入口因浏览器而异，不能承诺等同原生 App。 |
| 登录方式 | 邮箱 + 6 位一次性验证码 | 双方使用同一种方式，不要求同一社交账号体系或手机号地区；需要验证邮件送达。 |
| 账号入口 | 注册与登录合并 | 用户无需先判断是否已有账号；首次验证成功后进入自己的资料设置，已有账号恢复原资料与配对。 |
| 分发方式 | 网站链接 + 用户主动分享的配对邀请链接 | 首版不依赖应用商店分发；添加到主屏可在配对成功后提示，普通浏览器仍能使用。 |
| 首版语言 | 中文 | 面向当前已确认的中文交流人群；后续按真实用户需要增加英文。 |

替代路线：原生 iOS／Android 更适合后续重度小组件与系统通知，但会增加首版分发、适配和验证工作；邮箱密码也可跨设备使用，但需要增加密码设置与找回。当前核心验证是生活理解、真实配对与短留言，因此推荐先采用上表方案。

## 登录和邀请体验

1. 未登录时可以看产品说明及明确标识的示例，不展示真实伴侣信息。
2. 输入邮箱，请求验证码，在当前页面输入验证码完成验证；首版不依赖点击邮件登录链接。
3. 新用户进入已有的昵称／城市／节奏流程；已有用户恢复自己的资料与配对。
4. 有效登录期间日常打开尽量无需再次验证；主动退出或会话失效后重新登录。
5. 添加到主屏、换浏览器或换设备时，不假设一定继承当前会话。若需要登录，用同一邮箱恢复原账号，不新建重复配对。
6. 接收邀请时先显示邀请人昵称、城市与共享范围；登录流程保留邀请上下文，验证后返回原邀请页，用户明确接受才配对。邀请链接本身不作为登录凭证。
7. 邮箱只用于自己的账号，不向伴侣显示；登录验证码与配对邀请代码各有独立用途和有效期。

建议产品参数：验证码 10 分钟有效、60 秒后可重发；验证码一次使用，错误输入、过期、发送失败和频率限制分别反馈。发送和验证限制由服务端执行，用户输入不因错误丢失。具体认证服务还需确认能支持这些参数；它们不是任何供应商的默认值。

首版仅提供邮箱验证码入口，暂不增加密码、短信、微信、Google、Apple 登录。以后新增方式时，绑定到既有账号，不因入口变化创建第二个身份。

## 针对大陆与海外双方的发布验收

| 项目 | 发布前必须验证 |
| --- | --- |
| 国内外访问 | 用真实大陆网络和首批海外用户所在地网络检查首页、登录、邀请与同步；页面可打开不等于所有接口都可用。 |
| 邮件送达 | 用测试账号分别检查 QQ、163、Gmail、Outlook；记录到达时间、收件箱／垃圾箱位置及失败反馈。邮箱名单可按试用者实际邮箱增补。测试由产品方或自愿参与者自行请求验证码，不自动给他人发邮件。 |
| 跨手机使用 | iPhone Safari、Android Chrome，以及试用者实际使用的一款国内 Android 浏览器走完完整闭环；普通浏览器可用，不要求成功安装 PWA。 |
| 分享入口 | 在试用者常用通信工具打开邀请，检查是否能登录并接续；需要外部浏览器时有明确引导，不丢失邀请。 |
| 会话恢复 | 普通浏览器与主屏入口、两台设备分别验证；同一邮箱恢复同一个账号，邀请和配对不重复。 |
| 失败恢复 | 邮件未到可以重发或更换输入邮箱；登录错误／过期可重试；请求成功只表示请求已受理，不能声称已送达收件箱。 |

这些是验收任务，不代表已经验证上述网络或邮箱可用。现有原型仍只有本地模拟配对，没有真实邮件与账号。

## 下一步的技术选择

平台与登录方案确认后，再比较前端框架、认证服务、数据存储、邮件服务及部署区域。部署区域须结合真实网络测量，不根据“全球可用”宣传推定大陆可达性。

优先用两账号、两设备做最小闭环：邮箱登录 → 明确接受邀请 → 保存／读取双方作息和当前留言 → 暂停／解除后失去访问权限。服务采购与上线部署不属于本轮工作。

## 核对依据

- [PWA 安装机制](https://web.dev/learn/pwa/installation)：安装体验随浏览器与系统变化，iOS 主屏入口需要手动添加。旧页面部分能力描述可能随系统更新变化，本方案仅使用基础入口能力。
- [邮箱验证码机制](https://supabase.com/docs/guides/auth/auth-email-passwordless)：区分邮箱 OTP 与登录链接；可配置有效期。引用仅证明机制可用，不表示已选择 Supabase。
- [生产邮件配置](https://supabase.com/docs/guides/auth/auth-smtp)：若后续选择 Supabase，必须另行配置生产邮件服务，不能依赖其受限制的默认测试 SMTP。
