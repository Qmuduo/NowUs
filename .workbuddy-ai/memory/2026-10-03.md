## 首页改版：从配色问题改为版面问题（提交 `f0e6296` / `1ea0ddb`）

用户连续四次反馈：配色不喜欢 → 不高级 → 太暖、要时尚杂志 → **「页面可以重新设计吗？我觉得不好看」**。

**结论：换了两轮配色都没解决，问题在版面。** 首页骨架自第 88 轮起未变（标题行 → 两个钟 → 线 → 共同时间 → 线 → 留言 → 底栏），是普通 App 的堆叠列表。

**做法**：按 `mobile-ui-mockup` 技能出三版**结构不同**的版面（`design-history/2026-10-03-a/layout-options.html`）：封面式（通栏上下叠放）、版式网格（左标签栏 + 发丝线，无填充块）、对开式（左右等高 + 横跨两栏的通窗带）。

**用户选了对开式并给了参考图**（一个阅读类 App）。参考图的语言与我原先的黑白杂志调不同：浅冷灰底、白卡发丝线、**低饱和蓝**强调色、**浅蓝底分组面板**、顶部下划线标签、列表行「方块 + 粗标题 + 灰副行」。→ 合成版 `option3-with-reference.html`：对开式结构 + 参考图语言，夜晚用深藏青 `#1E2733` 而非纯黑（纯黑与浅冷体系冲突）。

**迭代中修掉两处自己造的错**：留言方块原本是假渐变缩略图（没有图片素材时应改用发送者方章）；共同时间面板有两行说同一件事（已合并）。

**状态**：`prototype/` 未被改动，这是设计探索；选定后再进原型并按协议送评。

## 第 117 轮：次级视图令牌对齐 → 评审判「无实质差别」（提交 `ba39de6`）

次级视图（日视图/节奏/弹窗）仍在用旧暖色令牌（`--day` 暖奶油、`--day-ink` 暖棕、`--sleep`、`--night-mid`、`--border` 带绿味，共 16 处），对齐到第 116 轮的中性冷灰家族。

**评审结果：无实质差别。** 逐像素比对后两版「结构、文案、几何完全一致」，只有一组中性灰的色温差异。

**但评审测出了方向是对的**：首页底色是冷中性灰（244,245,247），**B 的灰与首页同调，A 的偏暖偏绿、与首页不同调**。

**决定保留**：这是一致性修正而非设计偏好，方向被独立确认，且评审未指出损害。按规则 3.2，无实质差别即保留现状。

### 一条流程教训（已写进 round-117/review.md）

**改动太小，不构成「可选的差异」。** 「每轮只改一处」的「一处」≠「一处值得送评的改动」。
→ **选候选时先问：改完之后，两张图之间有没有一个能说出口的差异？** 若答案只是「色温更统一」，应并进别的轮次。批次还剩 3 轮，优先选能产出可描述差异的候选（共同时间面板信息密度、夜晚卡权重）。
